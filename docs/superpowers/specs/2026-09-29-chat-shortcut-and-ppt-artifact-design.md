# Chat Shortcut and PPT Artifact Registration Design

## Goals

1. Make `Ctrl+Enter` the send shortcut in every desktop input whose purpose is to send a conversation message. Plain `Enter` inserts a newline. Keep the visible send button, and do not submit while an IME composition is in progress.
2. Automatically register PPTX files generated by the PPT Agent/Skill in the desktop asset library and associate the artifact with the current assistant response.

This scope includes the shared AI/Agent/PPT/Writer composer and the Workflow AI sidebar. It excludes ordinary form fields, search boxes, workflow configuration textareas, and editors that do not send a conversation message.

## Existing Context

- `packages/workbench-ui/src/ai-elements/source.tsx` owns the shared `PromptInputTextarea` key handling. It currently submits on unmodified Enter and already protects IME composition.
- AI, Agent, PPT, Writer, media prompts, and the home composer use `WorkbenchPromptInput`; the Workflow AI sidebar composes the same `PromptInputTextarea` directly.
- The main AI composer currently advertises `Enter` to send and `Shift+Enter` for a newline.
- `apps/desktop/src/App.tsx` derives `allowArtifacts` from prompt wording or the `ppt_generate` workflow action. A chat that selects the PPT skill/agent can miss this policy if the wording does not match the artifact-intent expression.
- `apps/desktop/runtime/host.ts` registers files reported by completed local file-writing tool events, then emits artifact events. The desktop event handler registers the artifact and adds it to the current message and asset library.
- Artifact discovery must remain scoped to paths reported by this run; it must not scan the whole workspace.

## Approaches Considered

1. **Change the shared message textarea (recommended).** A single key handler covers all conversation composers and keeps newline/IME behavior consistent. Update all composer shortcut hints and add shared component tests.
2. **Add per-screen key handlers.** This would allow each screen to diverge and requires duplicating IME and form-submission logic across AI, Writer, media, and Workflow AI surfaces. Rejected because it is easy to miss an input or regress behavior.
3. **Change every HTML textarea/input globally.** This would alter ordinary forms, editors, and settings that are not conversation composers. Rejected as broader than requested.

For PPT artifacts, keep the existing event-based registration pathway. Make PPT skill/agent turns opt into artifact collection independently of prompt wording, then register only final PPTX files identifiable from that turn's completed file-writing tool events. Do not add a workspace-wide scan or a second asset-library registration mechanism.

## Design

### Conversation input behavior

- On a non-composing `Enter` keydown, submit only when `Ctrl` is pressed and `Shift` is not pressed.
- Plain Enter and `Shift+Enter` retain the browser textarea newline behavior.
- Preserve caller `onKeyDown` cancellation, form validation, attachment submission, disabled/streaming protections, and the visible submit button.
- Preserve native and React IME composition checks so Enter used to confirm Chinese/Japanese/Korean input never sends a message.
- Update user-facing hints at each composer that advertises a keyboard shortcut to `Ctrl+Enter` to send and `Enter` to insert a newline.

### PPT Agent artifact registration

- Resolve artifact collection as enabled when the active execution selects the PPT generation action or PPT-specific skill/agent, even when prompt wording alone does not match the existing artifact-intent pattern.
- Reuse the existing runtime completion callback, file-writing-tool path extraction, `workflow.artifact.register` service, artifact event, and message-part rendering.
- Emit/register only existing `.pptx` files reported by completed file-writing tool events from the current turn. Deduplicate repeated writes by relative path and report registration failures through the existing runtime warning path.
- Keep the resulting artifact visible in both the current assistant response and the asset library.

## Verification

- Component tests: Ctrl+Enter submits; plain Enter inserts a newline; Shift+Enter inserts a newline; composing Enter does not submit; caller-prevented keydown does not submit.
- Surface coverage: confirm the shared behavior applies to AI, Agent, PPT, Writer, media, home, and Workflow AI message composers, while ordinary textareas remain unchanged.
- Runtime tests: PPT-selected turns collect/register a completed `.pptx` even when prompt-intent matching is false; repeated writes deduplicate; missing files, unrelated paths, and registration failures do not create false asset rows.
- Run relevant workbench UI and desktop host tests, then typecheck/lint/build targets required by the repository.

## Constraints and Non-goals

- Desktop-only; no Dify integration.
- No automatic external-browser opening or change to preview behavior.
- No global change to non-chat form fields or editors.
- No arbitrary workspace scan and no new dependencies.
