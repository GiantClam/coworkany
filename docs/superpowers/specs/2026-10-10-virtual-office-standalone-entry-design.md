# 虚拟办公室独立入口与角色状态浮卡设计

日期：2026-10-10  
状态：设计已确认，规格待审阅  
Owner：Codex

## 目标

将虚拟办公室从首页中的嵌入区域提升为一个独立的工作空间入口，让用户通过角色形象快速了解真实工作状态，并从角色状态卡进入对应的 Agent、对话、工作流或产物页面。

本次设计保持 CoworkAny 现有品牌色、卡片语言、圆角和留白，不引入游戏 HUD 或编码工具风格。角色的动作和状态继续完全来自真实任务数据，不新增虚构的活动状态。

## 现状与问题

- `/dashboard` 首页当前直接挂载完整 `VirtualOfficeHome`，首页内容与办公室入口重复。
- Pixi 场景高度约为 250px，角色和设备信息在窄区域内竞争空间。
- 角色点击会直接导航，用户无法在办公室内先判断角色当前是否忙碌、等待处理或失败。
- 已有 React fallback 和 `RoleCard` 已包含大部分状态、任务与最近成果数据，但没有独立的浮卡交互。

## 设计结论

采用“独立路由 + 角色旁浮状态卡”方案：

1. 在现有 `WORKBENCH_ROUTE_MANIFEST` 增加 `/dashboard/office`，侧栏显示“虚拟办公室 / Virtual Office”。路由复用现有 `home` mode，避免把新的模式扩散到共享 Workbench 类型；桌面 App 在渲染分支中按路径挂载办公室页面。
2. `/dashboard` 保留工作台首页内容，不再渲染完整虚拟办公室；办公室只在独立路由中展示。
3. 独立页面使用可随窗口高度伸缩的主场景，桌面端目标高度约 520–680px，场景仍由 Pixi 增强、React 列表回退。
4. 点击角色只选中角色并打开旁浮卡，不立即跳转；点击“进入工作区”才导航到该角色的 `homeRoute`。
5. 同时最多显示一张浮卡；点击空白处、按 Escape 或切换角色时关闭/切换浮卡。浮卡内容随 `OfficeStore` 快照更新。

## 浮卡信息结构

浮卡使用现有 `OfficeRoleDefinition` 与 `OfficeRoleState`，从上到下展示：

- 角色名称、可用性和当前状态（空闲、工作中、排队中、等待你处理、已完成、失败等）；
- 繁忙程度：进行中、排队、待处理、失败数量；
- 当前任务设备：展示有限数量的任务项，点击后调用现有 `activateOfficeWorkItem`；
- 最近成果：展示最近工作项，点击后进入现有工作项目标路由；
- 唯一主操作“进入工作区”，执行角色的 `homeRoute`。

状态卡需具备可访问名称、焦点可达按钮和键盘关闭路径。Pixi 场景只发出 `onSelectRole(roleId)` 事件，不持有业务状态、浮卡状态或导航逻辑。React 父层负责选中角色、定位浮卡、关闭行为和路由动作。

## 浮卡定位与响应式行为

- 浮卡作为场景容器内的 DOM overlay 渲染，不嵌入 Pixi canvas，保证文本、按钮、焦点和屏幕阅读器语义完整。
- 选择角色时，场景提供角色锚点的相对坐标；React 将浮卡放在角色旁边，并在容器边缘自动翻转或夹紧，避免超出可视区域。
- 桌面宽屏优先放在角色右侧；靠近右边缘时放到左侧；窄窗口时改为场景底部的宽卡片。
- 浮卡打开期间，点击场景空白或浮卡外部关闭；点击浮卡内部不冒泡关闭。Escape 关闭后焦点返回触发角色。
- React fallback 中的角色入口使用同一 `OfficeRoleStatusCard`，以触发按钮为锚点，不依赖 Pixi 坐标。

## 组件与边界

- `VirtualOfficeHome`：订阅快照、管理 `selectedRoleId`、处理关闭和导航。
- `OfficeRoleStatusCard`（新组件）：只负责展示角色状态、任务和入口动作。
- `OfficeCanvasEnhancement` / `office-scene.ts`：将角色点击回调从“打开角色”语义收敛为“选择角色”，保留设备点击行为。
- `FallbackOfficeList`：继续完整可用；角色按钮打开同一状态卡或提供等价键盘入口，不依赖 Pixi。
- `App.tsx` 与 `routes.ts`：增加独立路由和渲染分支，复用现有侧栏和导航适配器。
- `virtual-office.css`：扩展大场景、浮卡定位、窄窗口回退和品牌色状态样式。

不新增依赖，不改变 `OfficeStore` 的真实状态投影、终态保留、资源清单和 Pixi 生产环境 gate。

## 状态与异常行为

- 角色不可用时仍显示状态卡，但“进入工作区”按钮置为不可用，并说明原因。
- Pixi 加载失败时显示 React 列表和等价状态卡；页面仍可完成查看和进入操作。
- 没有角色时显示现有空状态。
- 状态快照更新时保留当前选中角色，只刷新卡片内容；角色被移除时自动关闭浮卡。
- 浮卡不改变任务执行、取消或重试语义；任务动作继续走现有导航和客户端接口。

## 验收与验证

至少验证以下场景：

1. 侧栏出现独立入口，进入 `/dashboard/office`；首页不再重复渲染完整办公室。
2. macOS 窗口下办公室场景明显大于当前 250px，并在窄窗口可用。
3. 点击 Pixi 角色和 React fallback 角色都能打开同一类状态卡。
4. 状态卡正确显示状态、四类计数、任务/成果和“进入工作区”。
5. 点击任务、成果和进入按钮分别到达已有目标路由。
6. 点击空白、Escape、切换角色可关闭或切换浮卡；键盘和屏幕阅读器可用。
7. Pixi 失败、资源清单失败和无任务场景仍可用。
8. 中英文文案、现有品牌色和对比度不回归。

验证范围以 macOS 为准：定向虚拟办公室测试、桌面测试、typecheck、Vite 构建、资源/bundle 校验和 macOS 原生 smoke；不宣称 Windows 验证。
