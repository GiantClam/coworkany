# 紧凑型 AI 对话输入框设计

日期：2026-09-29
状态：已确认

## 背景

当前 AI 对话输入区默认占用较大的垂直空间。输入框至少约 88px 高，模型与推理深度是两个并列入口，知识库启用后还会常驻额外按钮。即使用户没有输入长文本、添加附件或选择知识库，输入区仍会持续压缩消息展示区域。

本次调整将输入区改为类似 ChatGPT 网页端的紧凑结构：默认一行、最多三行；模型与推理深度共用一个入口；上传文件和知识库统一进入“+”菜单。实现必须优先复用仓库中的 AI Elements 组件。

## 目标

- 空输入状态只占一行，整体高度约 50–54px。
- 输入内容自动增高，最多显示三行；超过三行后 textarea 内部滚动。
- 模型和推理深度通过一个触发器、一个菜单完成选择。
- 上传文件和选择知识库都从“+”菜单进入。
- 附件和知识库只在被选择后显示轻量上下文状态。
- 保留现有发送、停止生成、附件拖放、模型能力约束、选择持久化和中文输入法行为。
- 降低输入区对消息列表的滚动留白和遮挡。

## 非目标

- 不改变模型目录、推理深度定义或后端请求协议。
- 不改变知识库检索、附件解析和上传限制。
- 不重做完整聊天页面或消息卡片。
- 不新增第三方依赖。

## 布局

输入区常态采用四列布局：

```text
┌─────────────────────────────────────────────────────────────┐
│  ＋   输入消息…                     GPT-5.6 · 自动      ↑  │
└─────────────────────────────────────────────────────────────┘
```

```text
[ + ] [ 自适应 textarea ] [ 模型与推理 ] [ 发送/停止 ]
```

容器使用 CSS Grid。按钮固定宽度并靠底部对齐，textarea 占用剩余宽度。默认状态的输入区高度由 34px 控件高度和约 8px 上下内边距组成。

textarea 使用 24px 行高，初始一行，最大高度 72px。内容超过三行后保持 72px 并启用内部纵向滚动。整个输入容器在无上下文时约 50–54px，高度达到三行时约 92px。

键盘行为：

- Enter 发送。
- Shift+Enter 换行。
- 输入法组合状态下 Enter 不发送。
- 发送后恢复一行高度并重新聚焦。
- 生成期间 textarea 只读，发送按钮变为停止按钮。

## 附件与知识库入口

“+”按钮使用 AI Elements 的 `PromptInputActionMenu` 组件族，一级菜单包含：

```text
┌────────────────────────────┐
│ 📎 上传文件                │
│ 🗄 选择知识库            › │
└────────────────────────────┘
```

“上传文件”复用现有隐藏 file input、文件类型、数量和大小限制。“选择知识库”打开二级知识库面板，包含搜索、知识库多选、使用全部已启用知识库和关闭知识库。

选择知识库后，工具栏中不再出现独立的知识库按钮和关闭按钮。“+”按钮通过一个数量徽标表示已添加的附件和知识库上下文总数。

已选择的上下文显示在输入行上方：

```text
[品牌规范 ×] [产品资料 ×] [report.pdf ×]
```

上下文区域满足以下规则：

- 没有附件或知识库时不渲染，不占高度。
- 单行横向滚动，不因项目数量增加而换成多行。
- 每项可独立移除。
- 附件解析中显示加载状态。
- 失败附件显示重试和移除操作。
- 拖入文件时只改变容器描边；文件落下后才显示上下文项。

## 模型与推理深度

主界面只保留一个触发器：

```text
GPT-5.6 Luna · 自动
Claude Sonnet · 高
```

菜单根层级包含模型入口和推理深度选项：

```text
┌────────────────────────────┐
│ 模型                       │
│ GPT-5.6 Luna             › │
├────────────────────────────┤
│ 推理深度                   │
│ ✓ 自动                     │
│   快速                     │
│   标准                     │
│   深度                     │
└────────────────────────────┘
```

点击模型项进入可搜索的模型列表。选择模型后回到根层级，并立即按照新模型的能力重新计算有效推理深度。推理选项取自现有 `reasoningCapabilities`，不维护另一套静态配置。

状态规则：

- 当前推理深度在新模型上不可用时，通过现有 `normalizeReasoningEffort` 归一到有效值。
- 只有一个推理选项时，推理区域显示该值但不可操作。
- 业务场景锁定模型时，模型项只读；推理深度仍按能力开放。
- 切换结果继续使用现有模型和推理深度持久化函数。
- 生成期间整个菜单禁用。
- 触发器过长时省略模型名称中部或尾部，始终保留推理摘要。

## 组件设计

AI Entry 当前使用一套本地 Prompt Kit。实施时改用或对齐共享 AI Elements 原语：

- `PromptInput`
- `PromptInputHeader`
- `PromptInputBody`
- `PromptInputTextarea`
- `PromptInputSubmit`
- `PromptInputActionMenu`
- `PromptInputActionMenuTrigger`
- `PromptInputActionMenuContent`
- `PromptInputActionAddAttachments`
- `PromptInputActionMenuItem`
- `Attachments`
- `ModelSelector`

新增两个窄职责组件：

### `CompactComposerRow`

负责输入行的 Grid 布局、按钮底部对齐、textarea 一至三行自动增长和响应式收缩。它不读取模型、附件或知识库业务状态。

### `CombinedModelSelector`

接收模型列表、当前模型、推理能力列表和两个变更回调。它负责模型搜索、根层级与模型列表之间的切换、能力相关禁用状态和触发器摘要，不负责持久化或请求参数转换。

AI Entry 页面继续持有业务状态和副作用。知识库二级面板作为“+”菜单的业务内容留在 AI Entry 层，避免把知识库领域逻辑塞进通用 PromptInput。

组件结构：

```tsx
<PromptInput>
  <PromptInputHeader>
    <ComposerContextRail />
  </PromptInputHeader>

  <CompactComposerRow>
    <ComposerAddMenu />
    <PromptInputBody>
      <PromptInputTextarea rows={1} />
    </PromptInputBody>
    <CombinedModelSelector />
    <PromptInputSubmit />
  </CompactComposerRow>
</PromptInput>
```

## 数据流

1. textarea 更新现有 `input` 状态。
2. “+”菜单调用现有附件选择或知识库选择逻辑。
3. 附件与知识库状态组合成只用于展示的上下文列表；请求仍分别使用现有 `attachments` 和 `selectedKnowledgeDatasetIds`。
4. 模型选择更新 `selectedModelId` 并持久化。
5. 选中模型变化后重新计算 `resolvedReasoningEffort`。
6. 推理深度选择更新 `selectedReasoningEffort` 并持久化。
7. 发送继续调用现有 `handleSend`，请求载荷不变。

## 响应式行为

- 宽屏显示完整模型名称和推理标签。
- 中等宽度限制触发器宽度，模型名称省略，保留推理标签。
- 窄屏隐藏 provider 标识，并将推理标签缩短为“自 / 快 / 标 / 深”。
- 极窄宽度下模型触发器可仅显示模型图标与推理简称；“+”和发送保持 34px 可点击区域。
- 上下文栏始终保持单行横向滚动。

## 可访问性

- “+”、模型菜单、发送、停止和移除操作都有中文与英文 `aria-label`。
- 菜单使用现有 Radix/AI Elements 焦点管理与 Escape 关闭行为。
- 模型和推理选项使用单选语义；知识库使用多选语义。
- 状态不能只依赖颜色，选中项同时显示勾选图标。
- 禁用状态向辅助技术暴露。

## 错误处理

- 文件超限、解析失败和模型不支持附件沿用当前错误提示。
- 知识库加载失败时菜单显示错误状态，并保留已选择项的摘要。
- 模型列表为空时触发器显示“无可用模型”，发送保持禁用。
- 当前模型失效时沿用现有回退选择逻辑。
- 菜单关闭不会清除尚未发送的输入、附件或知识库选择。

## 验证

自动化测试覆盖：

- textarea 初始一行、增长至三行、超过三行后滚动。
- Enter、Shift+Enter 和中文输入法组合行为。
- “+”菜单同时提供上传与知识库入口。
- 选择和移除知识库不会重新出现独立知识库工具栏。
- 模型和推理深度通过一个触发器访问。
- 模型变化后推理深度正确归一。
- 锁定模型、无推理能力、加载中和生成中状态。
- 附件上传、拖放、失败重试和移除不回归。
- 发送请求中的模型、推理、附件和知识库字段不变。

视觉验收覆盖桌面宽屏、窄屏、空输入、三行输入、多附件、知识库多选、生成中和错误附件状态。重点检查输入区不遮挡最后一条消息，并同步缩减消息列表的底部滚动留白。

## 验收标准

- 无上下文、空输入时输入区整体高度不超过 56px。
- textarea 最多显示三行，第四行开始内部滚动。
- 主工具行只有“+”、textarea、组合模型入口、发送/停止四类元素。
- 主界面不存在独立推理选择器和常驻知识库控制。
- 附件与知识库都能从“+”菜单完成添加。
- 模型与推理深度都能从同一入口完成选择。
- 现有发送请求和状态持久化行为保持兼容。
